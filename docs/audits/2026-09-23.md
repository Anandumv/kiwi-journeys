# Kiwi Journeys website review — 23 September 2026

## Outcome

Implemented targeted improvements to the existing site, including a security update to Next.js 16.3.6. Changes are local and have not been deployed. A whole-site review cannot establish that every possible failure is absent; the checks and remaining limits are recorded below.

## Verified problems corrected

- Tour links with an unknown `price` parameter crashed the catalogue. Invalid values now fall back safely; filters follow the URL when using browser history, preserve unrelated query parameters when edited, and update without a server request per keystroke. Empty results offer a clear-filters action.
- Fully booked dates could not be selected, so the waitlist was unreachable. Customers can now select a sold-out date and a specific departure, including a sold-out departure on a day with other available times. The form resets when changing departure.
- The waitlist API accepted departure IDs unrelated to the selected tour. It now validates ownership, scheduled status, and a future departure.
- Waitlist notifications ignored active holds and marked entries notified after failed delivery. Capacity now subtracts unexpired holds, unpublished tours are excluded, and rejected sends remain pending. These changes do not reserve seats for waitlisted customers.
- Reveal wrappers emitted `opacity:0` in server HTML. Content now renders visibly without JavaScript, with optional CSS movement and reduced-motion support.
- The mobile menu did not close with Escape. It now closes and returns focus to its trigger; navigation has labels and current-page indicators. Added a skip link, global keyboard focus treatment, and selected-image announcements in galleries.
- The footer overflowed at tablet widths. Its columns now adapt across tablet and desktop, with wrapping for long email addresses.
- Low-contrast labels, secondary text, and white-on-gold booking buttons were corrected across the audited flows.
- Homepage cancellation text promised a full refund at 48 hours while the existing terms and FAQ required more than 72 hours. The homepage now follows the existing policy; this review does not establish legal approval of that policy.
- Removed an inherited homepage canonical from unrelated pages, added the sustainability canonical, prevented duplicate homepage branding in its title, marked private/account/booking/admin workflows noindex, removed noindex legal pages from the sitemap, and stopped generating invented last-modified timestamps on every request.
- Removed an unused site-wide testimonial database query. Deferred the scroll-controlled hero video until scrolling. Expanded the loading placeholder to a full viewport to keep the footer out of the initial loading viewport.
- Updated Next.js and compatible vulnerable transitive dependencies. Initial production dependency audit: 9 entries (1 critical, 6 high, 2 moderate). Final: 3 high entries, all in one Prisma tooling dependency chain.

## Production and remaining requirements

### Visual refinement requested during review

The follow-up direction was to avoid a generic AI-generated appearance. The existing brand palette, logo, hero, URLs, and CMS content remain the foundation. The homepage now uses open photographic tour listings instead of heavily rounded card shells, a ruled destination directory instead of inactive placeholder cards, plain guest quotations instead of avatar/quote decorations, and a practical contact invitation instead of “your adventure awaits.” Decorative blobs, leaf ornaments, repeated badges, and alternating dark promotional bands were removed from the homepage. Experience imagery now prefers a published tour in the corresponding category. Existing reviews and business facts were not invented or rewritten. The booking UI keeps its functional controls.

After the visual refinement, the latest mobile Lighthouse run scored **89 performance, 100 accessibility, 100 best practices, 100 SEO**, with LCP 3.7 seconds, blocking time 10 ms, and CLS 0. Scores vary between lab runs; the earlier 92 is not presented as the latest result. Build, TypeScript, HTTP, and browser checks were rerun for the revised layout. Screenshots of the listings are `outputs/audit/2026-09-23/tours-design-desktop.png` and `tours-design-mobile.png`.

Read-only check of `https://kiwi-journeys-production.up.railway.app/api/health` returned:

```json
{"status":"ok-degraded","db":"ok","payments":false,"webhook":false,"email":false,"scheduler":true}
```

1. **Launch blocker:** configure Stripe, its webhook, and email delivery through existing deployment/credential management. Then verify payment, 3DS, retry, refund, voucher purchase, and real email delivery in test mode. No real charge, refund, or message was sent in this review. No credential values were printed or requested.
2. **Dependency follow-up:** Prisma 6.19.3 → `@prisma/config` → `deepmerge-ts` retains a recursive-object denial-of-service advisory. npm proposes a breaking downgrade to Prisma 6.12.0. This was not applied. The affected dependency is used by Prisma configuration tooling; this review has not established a remotely reachable exploitation path in this application. Do not confuse that limitation with resolution of the advisory.
3. **Operations:** waitlist sending still uses the existing single-replica scheduler and lacks the transactional outbox guarantees of booking/refund emails. A process crash after provider acceptance can still produce a duplicate on retry. Daily notification jobs and process-local rate limits need redesign before multi-replica scaling.
4. **Business review:** confirm photography rights, testimonial authenticity, business details, group-size promises after the vehicle-capacity migration, and legal content. These cannot be established by automated testing or invented replacements.
5. **Coverage limits:** no independent penetration test, authenticated admin mutation tour, complete cross-browser/device matrix, screen-reader user study, production load test, or field Core Web Vitals measurement was performed. Browser waitlist writes are intercepted; backend regressions use provider/database doubles. Existing isolated integration tests cover booking concurrency and payment state transitions.
6. **Release:** these improvements are not live. Review the local diff and deploy through Railway; verify health and public flows after deployment. Existing production service configuration must be resolved to claim booking readiness.

## Reproduce

```sh
npm test
npm run test:integration
npm run build
npm run typecheck
# Use next start directly for audit serving: do not migrate/seed operational data.
node node_modules/next/dist/bin/next start --port 3101
AUDIT_BASE_URL=http://localhost:3101 node scripts/audit-http.mjs

# Audit-only tools live outside the application dependency tree.
npm install --prefix /tmp/kiwi-audit-tools playwright axe-core lighthouse
AUDIT_TOOLS=/tmp/kiwi-audit-tools AUDIT_BASE_URL=http://localhost:3101 node scripts/audit-browser.mjs
```

Chrome must be installed for the browser script. Its mock waitlist email uses `example.invalid`; it does not contact a recipient.
